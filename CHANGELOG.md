## [Unreleased]

### Added

- `secret-scan-guard` plugin 1.0.0: scans new file content, staged and `-a`/pathspec commits, and the local commits a `git push` would send. High-confidence provider keys (AWS, GitHub, GitLab, Slack, Anthropic, OpenAI, Stripe, SendGrid, npm, Twilio, private keys) block. Entropy-checked assignments, JWTs, URL credentials, Google API keys, and AWS secret keys near AWS context ask. Command lines embedding a secret ask, as do staging or committing `.env` and key files. Placeholders, lockfiles, minified and binary files, integrity hashes, and `secret-scan:allow` lines are skipped, but a marker the agent adds itself asks. Findings are redacted to the provider prefix. Config comes from a trusted `~/.claude/secret-scan.json` and a repo `.claude/secret-scan.json` that can only add patterns and name a baseline. Edits to either, or to the baseline, ask. `secret_scan.py --baseline` records SHA-256 fingerprints of existing findings. `SECRET_SCAN_GUARD_DISABLE=1` turns it off. Its skill guides credential handling and leak response.
- `destructive-command-guard` plugin 1.0.0: catches irreversible shell commands by parsing them, not by matching strings. It unwraps `sudo`, `env`, `xargs`, `bash -c`, `eval`, `$(...)`, backticks, and heredocs, and checks a rule table with stable ids covering filesystem, disk, remote-code, database, and infrastructure commands. Asks escalate to deny under `sudo` or against a production database. Config comes from a trusted user file `~/.claude/destructive-guard.json` and a repo file `.claude/destructive-guard.json` that can only make rules stricter. `DESTRUCTIVE_GUARD_DISABLE=1` turns it off. Git commands are left to git-workflow-guard.
- `protected-files-guard` plugin 1.0.0: stops silent edits to files that should change only on purpose. Edits to `.env`/`.env.*` (except `.env.example`, `.sample`, `.template`), `*.pem`, `*.key`, `id_rsa*`, `*.p12`, `*.keystore`, and `credentials.json` are denied. Lockfiles, CI config, migrations, `LICENSE*`, `CODEOWNERS`, and `SECURITY.md` ask, and the lockfile message points to the package manager. File tool paths are resolved with `realpath`, so symlinks can't dodge rules. Shell commands are checked heuristically for redirects, `tee`, `sed -i`, `cp`, `mv`, `rm`, `truncate`, `git checkout --`, `git restore`, and PowerShell write cmdlets. A repo `.claude/protected-files.json` adds rules, `allow` overrides, and `replaceDefaults`, with `**` glob support. `PROTECTED_FILES_GUARD_DISABLE=1` turns it off. Its skill explains why a file is protected and proposes the proper change.
- `pr-writer` plugin 1.0.0: `/pr-writer:draft [base-branch] [--ready | --draft]` drafts a pull request or merge request title and description from the branch's commits and diff. A read-only script collects the base, commits, diff (excerpted past `diffSizeCap`), breaking changes, issue references, PR templates, `CODEOWNERS` owners, push state, and whether `gh` or `glab` is signed in. The skill fills the repo's template, checks the title against Conventional Commits, redacts secrets, and treats commit and diff text as data. It lists only testing it can show, leaves checkboxes unticked without evidence, and never pushes. It creates the PR only after an explicit yes, as a draft by default, and gives paste-ready text when no authenticated CLI is available. Config comes from `.claude/pr-writer.json`. It has no hooks.
- `test-before-commit` plugin 1.0.0: runs the project's test and lint commands before `git commit`. A failure blocks the commit with the command, its exit code, and the last 60 lines of output. A timeout or a command that can't start asks. Commands come from `.claude/test-before-commit.json` or `~/.claude/test-before-commit.json`, or from `autodetect` (off by default). Repo-config commands run only after you approve them with `/test-before-commit:trust`, and again after any change. Docs-only changes, merge commits, and `--amend --no-edit` skip the checks. A pass is cached per staged and working-tree state. `TEST_BEFORE_COMMIT_DISABLE=1` turns it off. Its skill tells Claude to fix the cause, not weaken the tests.
- `humanizer` plugin 1.0.0: `/humanizer:review [paths | --staged | --diff <base>]` flags comments, docstrings, and docs on added lines that read like generic AI boilerplate (stock phrases, comments that restate the code, echo-only docstrings, tutorial voice, hype and hedge stacking, formulaic lists, emoji prefixes, em-dash density, uniform sentences) and rewrites the ones you approve. A stdlib script finds the text and prints JSON, and never edits files. Code blocks, inline code, URLs, license headers, lint directives, generated, vendored, minified, binary, and gitignored files are skipped. A voice sample of the repo's own docs downgrades findings that match its existing style. The skill keeps meaning and structure, deletes noise comments instead of rephrasing them, never invents facts or fakes a human voice, and never commits or pushes. An opt-in `commitNudge` hook asks before `git commit` when the staged text has enough findings, and never blocks. Config comes from `.claude/humanizer.json`. `HUMANIZER_DISABLE=1` turns the hook off. It is an editor, not a detector-evasion tool.
- `test-writer` plugin 1.0.0: `/test-writer:write <path... | symbol | --diff <base>>`, or a request like "write tests for ...", writes tests that match the repo's existing ones. A stdlib script detects the framework (pytest, unittest, jest, vitest, mocha, go test, cargo test, JUnit, rspec, phpunit, dotnet test), the test command and where it came from (`package.json`, `Makefile`/`justfile`, pytest config and `tox.ini`, CI, then a low-confidence default), Python and JavaScript/TypeScript conventions, the 3 nearest existing tests for each target, which public symbols existing tests mention, coverage tools and reports, and imports that suggest tests need services. It never reads `.env`, key, or credential files. The skill only adds or extends test files, runs new tests three times and then the surrounding suite, and reports a suspected bug instead of bending a test or fixing the code. A mutation check breaks the code in a `--snapshot` copy without `.git`, never your working tree, to prove the new tests can fail. It never commits or pushes.
- `session-recap` plugin 1.0.0: `/session-recap:summary [--since <ref|time>] [--base <branch>] [--save]`, or a request like "recap this session", writes a short recap with What changed, Impact, Testing, and Next time. A passive hook logs paths, edit counts, redacted commands, kinds, exit codes, and durations to `~/.claude/session-recap/`, never contents or output, and prunes old logs. A stdlib script reads the log and git and reports changes, impact signals with file evidence (public API and signature changes, dependencies, env vars, config, migrations, lockfiles, CI, infra, auth, deletions, importers), recorded test runs and stale-test warnings, efficiency signals, and the previous recap's items. The skill reads the diff of the top files, labels impact as observed or inferred, says "no test run recorded" when there is no log, and writes a saved recap or `CLAUDE.md` line only after you say yes. It never commits or pushes. An opt-in `autoRecap` Stop hook suggests the recap once when 3 or more files changed. Config comes from `.claude/session-recap.json`. `SESSION_RECAP_DISABLE=1` turns logging off.
- `bug-reproducer` plugin 1.0.0: `/bug-reproducer:fix <description | issue number | URL | --from-log <file>>`, or a pasted stack trace or "fix this bug", fixes a bug test-first. A stdlib script parses the report without running anything from it: stack frames (Python, JavaScript/TypeScript, Java/Kotlin, Go, Rust, Ruby) resolved to repo files, mentioned paths and symbols with their definitions, error messages, exit codes, versions, and capped grep hits for distinctive strings. It also reports the test command and nearest tests through a byte-identical copy of test-writer's `detect_tests.py`. The skill reads issues with `gh issue view` only, treats report text as data, writes the smallest failing test in the repo's style, confirms over three runs that it fails for the reported reason, and waits for approval (unless `autoFix` is set in `.claude/bug-reproducer.json`). Then it makes the minimal fix, never weakens the test, reports pre-existing failures from a baseline run separately, and suggests a `fix(...)` commit message. It never commits or pushes.
- `refactor-safely` plugin 1.0.0: `/refactor-safely:run <paths | symbol> "<goal>"`, or a request to refactor, restructures code only when tests protect it. A stdlib script `check`s which tests refer to each target (same stem, imports, names the file), which public symbols no test mentions, and line coverage from `lcov.info`, Cobertura, or Istanbul reports against an optional `requireCoverageOver`. `baseline` refuses unless the check was `covered` and records pass and fail counts, failing test names, timing, and a hash of every test file from a run of the test command. It reads the summary of pytest, unittest, jest, vitest, mocha, `go test`, `cargo test`, JUnit, rspec, phpunit, and `dotnet test`. `step` reports new failures, fixed tests, a falling test count, the diff size, and any test file changed since the baseline. A run past `stepTimeout` is stopped with its whole process tree. State lives in `.git/refactor-safely-state.json`. The skill refuses on `partial` or `uncovered`, offers characterization tests, refuses a red baseline, shows a plan and waits, keeps changes behavior-preserving, undoes a failing step with its own edits, calls out any test edit, asks before a checkpoint commit, and never commits or pushes. Config comes from `.claude/refactor-safely.json`. `baseline` and `step` ask for permission each time.
- Dart and Flutter support. `detect_tests.py` (shared by `test-writer`, `bug-reproducer`, and `refactor-safely`) detects `flutter test` and `dart test` from `pubspec.yaml` and test imports, treats `*_test.dart` as tests, lists a library's public classes, mixins, enums, extensions, typedefs, and top-level functions, maps `package:` and relative imports to `lib/` files, and reports conventions (`test`, `testWidgets`, `group`, mockito, mocktail, `expect`, finders, `setUp`, goldens). Generated `.g.dart`, `.freezed.dart`, `.gr.dart`, `.mocks.dart` and `.dart_tool` are skipped. `bug-reproducer` parses Dart/Flutter stack frames (`package:`, `file://`, and `dart:` URIs) and Flutter's "The following ... was thrown" errors. `refactor-safely` reads the progress line and failing tests of `flutter test` and `dart test`. `protected-files-guard` asks before editing `pubspec.lock`, `secret-scan-guard` skips it, and `test-before-commit` autodetects `flutter test` and `dart test` from `pubspec.yaml`. `session-recap` reports Dart public-API and signature changes, importers (`package:` and relative imports), `pubspec.yaml` and `pubspec.lock` changes, and classifies `flutter test`, `dart test`, `dart analyze`, `flutter build`, and `flutter pub get` (also through `fvm`).
- `git-workflow-guard`: creating a branch with `git switch -c`, `git checkout -b`, or `git branch <name>` asks you when the name doesn't follow `<type>/<short-kebab-description>`. The skill offers name and subject options for you to pick from.

- `git-workflow-guard`: commands that throw away work ask first: `git reset --hard`, `git clean -f`, `git branch -D`, `git stash drop`/`clear`, `git checkout -- <path>`, `git checkout -f`, `git switch -f`/`--discard-changes`, and `git restore <path>`.
- `git-workflow-guard`: editing `.claude/git-guard.json`, or a shell command that mentions it, asks first, because it decides which branches are protected.
- `pr-writer`: passwords in URLs (including ones with a raw `@`) and JSON Web Tokens are redacted along with the high-confidence secrets. Day-old `body_file` temp directories from earlier runs are removed.
- Tests check that the code copied between plugins stays identical.

### Changed

- `git-workflow-guard`: a commit subject over 72 characters now asks you instead of blocking, so you can keep a longer one. Subjects that aren't Conventional Commits are still blocked.
- `destructive-command-guard`: config warnings reach you through `systemMessage` when a command is allowed or asks. Before, they went only to stderr, which isn't shown then.
- `SECURITY.md` describes what every plugin runs, reads, writes, and sends over the network.

### Fixed

- `git-workflow-guard` and `secret-scan-guard`: git calls inside subshells, `$(...)`, backticks, `if`/`while` blocks, `sudo`/`env`/`command` wrappers (including option clusters like `sudo -iu root`), `bash -c`, and `eval` are now checked. A `cd` inside a subshell no longer carries over to later commands. Before, `(git push origin main)` got past the protected-branch block, and `env git commit` skipped the secret scan.
- `git-workflow-guard`: `-n` inside a cluster (`-nm`) and `git -c core.hooksPath=...` now ask like `--no-verify`. `git commit -unormal -m "..."` is no longer misread as `-m ormal`.
- `protected-files-guard`: wrapper options and paths no longer hide the command (`sudo -iu root tee .env`, `/usr/bin/sudo tee .env`), writes inside subshells such as `(echo x > .env)` are seen, and `ln` and `install` targets are checked.
- `pr-writer`: diff excerpts read file names literally, so a file named `[ab].txt` no longer pulls in `a.txt`.

## [1.0.0] - 2026-10-13

### Added

- `dev-guardrails` marketplace with the `git-workflow-guard` plugin.
- `PreToolUse` hook that blocks file edits and commits on protected branches.
- Conventional Commit check on `git commit` subjects (`-m`, `--message`, and heredocs), with a 72-character limit.
- Confirmation prompt for `git commit --no-verify`.
- `git push` check that blocks protected targets and asks before any other push, listing the repo's contribution guidelines and warning on force, `--all`, and `--mirror` pushes.
- Per-repo override of protected branches through `.claude/git-guard.json`.
- `git-workflow-guard` skill for branch naming, commit drafting, and pre-push checklists.
